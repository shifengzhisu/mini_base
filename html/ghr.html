一、背景知识：读懂脚本前你需要知道的

1.1 这两个脚本在做什么？

这两个脚本属于 IQVIA（全球医药数据分析公司）内部数据处理流程，用于维护中国药品的两份核心名单：

  • 参比制剂名单 — 国家药监局（NMPA）定期发布的"标杆药品"列表，仿制药需要和它对比
  • 一致性评价名单 — 已通过质量一致性评价的仿制药列表（简称"过评"）

每个月/每个季度，NMPA 都会发布新增和勘误信息，这两个脚本就是把最新数据更新到 IQVIA 的内部数据库（NDF）中。

1.2 什么是 VFP？

脚本使用的语言是 Visual FoxPro (VFP)，一种老牌桌面数据库语言。你可以把它理解为"用命令行操作 Excel 表格"：

  • USE 表名 = 打开一个表格文件
  • BROWSE = 在屏幕上预览表格内容
  • SELECT = 切换到某个已打开的表格 / SQL查询
  • APPEND FROM = 从另一个文件追加数据行
  • REPLACE ALL ... WITH ... FOR ... = 批量修改符合条件的数据
  • INDEX ON ... TO ... = 给表格建索引（为了后续关联查找）
  • SET RELATION TO ... INTO ... = 两张表通过某个字段建立关联（类似Excel的VLOOKUP）
  • DELETE ALL FOR ... = 标记删除符合条件的行
  • PACK = 物理删除已标记的行
  • && = 注释（不执行的说明文字）

1.3 核心术语表

NDF
National Drug File，IQVIA的药品主数据库，包含所有在中国销售的药品信息
PFC (Pack Form Code)
IQVIA内部的药品唯一编码，每个规格的药品有一个PFC
DN (Drug Number)
IQVIA内部的药物编号，同一个DN下可能有多个PFC（不同规格）
CPA
药品包装档案表，存储批准文号(pzwh)、厂家(manu)、规格(specifi)等信息
GQCE
Generic Quality Consistency Evaluation，一致性评价标记总表
ATC
解剖学治疗学化学分类系统，用于药品分类的国际编码
参比制剂 (Reference Preparation)
NMPA指定的仿制药质量对标的原研/标杆药品
过评 (PASS)
通过一致性评价的药品，质量达到与原研药一致的标准
pzwh (批准文号)
NMPA颁发的药品上市许可编号，格式如"国药准字H20000001"
药融云 / CIPP
两个外部数据源：药融云是第三方医药数据平台；CIPP是上市药品目录集
脚本 1

参比制剂脚本 — 更新参比制剂总表并同步PFC

PRG 1: 追加新增+勘误 → PRG 2: 应用勘误修改 → PRG 3: 匹配PFC编码 → PRG 4: 同步到GQCE总表
1 PRG 1：追加新增参比制剂 + 导入勘误数据
目标：

将NMPA最新发布的参比制剂（新增 + 勘误）追加到"仿制药参比制剂"总表中

第一步：初始化环境
SET DEFAULT TO "C:\...\2026\4m"
设置工作目录为 2026年4月 的数据文件夹（每期需修改路径）
SET DELETED ON
开启"已删除记录不可见"模式，被标记删除的数据不会参与后续操作
SET EXACT ON
字符串比较时要求精确匹配（"ABC" 不等于 "ABCD"）
第二步：将新增参比制剂追加到总表
USE 仿制药参比制剂
打开上一期的参比制剂总表（需事先从公盘复制并去掉日期后缀）
BROWSE last nowait
预览表格内容（显示最后几行），不阻塞后续命令
COPY STRUCTURE to CBZJ_STRU
复制总表的"表头结构"（只有列名，没有数据）到一个临时表 CBZJ_STRU
use CBZJ_STRU → COPY TO CBZJ_新增
再拷贝一份空结构表，命名为"CBZJ_新增"
use CBZJ_新增 → APPEND FROM ...CBZJ_新增.csv type csv
从CSV文件导入本期新增的参比制剂数据（路径需根据实际修改）
SELECT 仿制药参比制剂 → APPEND FROM CBZJ_新增
将新增数据追加到总表末尾
第三步：导入勘误数据
COPY TO CBZJ_勘误 → APPEND FROM ...CBZJ_勘误.csv type csv
用同样的方法创建空表→导入勘误CSV（NMPA发布的修正信息）
第四步：核验勘误数据的准确性
INDEX on ALLTRIM(序号) to t1
对总表的"序号"字段建索引（加速查找）
SET relation to ALLTRIM(序号) into 仿制药参比制剂 addi
让勘误表通过"序号"关联到总表（类似Excel的VLOOKUP按序号匹配）
&&肉眼比对药品通用名是否一致
需要人工检查：勘误表的药品名与总表是否对得上（NMPA曾出现序号错误）
注意：PRG 1 执行完后需要人工 review NDF 中是否已添加该产品，如果已有 PFC，需手动补充至总表中。
2 PRG 2：将勘误内容应用到总表
目标：

用勘误数据覆盖更新总表中对应记录的各字段

建立反向关联并批量替换
INDEX on ALLTRIM(序号) to s1
对勘误表的序号建索引
SELECT 仿制药参比制剂 → SET relation to ALLTRIM(序号) into CBZJ_勘误
总表通过序号关联勘误表（方向反过来，这次是从总表去查勘误表）
repla all 药品通用名 with cbzj_勘误.药品通用名 for !EOF('CBZJ_勘误')
如果在勘误表中找到了匹配记录（!EOF = 没到文件尾 = 找到了），就替换"药品通用名"
repla all 英文名称/规格/持证商/备注1/备注2/追加时间 ...
同理，逐个替换：英文名称、规格、持证商、备注1、备注2、追加时间
BROWSE last for "第104批"$追加时间
预览本批次被勘误修改的记录（需根据实际批次号修改"第104批"）
原理：!EOF('CBZJ_勘误') 的意思是"勘误表中存在匹配的记录"。VFP中，当关联查找没找到结果时，指针会指向文件末尾(EOF)，所以 !EOF 就是"找到了"的意思。
3 PRG 3：从NDF提取新增PFC，与参比制剂匹配
目标：

为参比制剂总表中的药品补充 IQVIA 内部的 PFC 编码

第一步：从NDF提取本期新增产品
USE ndf
打开NDF主数据库
Sele pfc,name,atc,...from ndf into dbf ndf_new where period='0426'
用SQL查询，提取2026年4月新增的产品数据到 ndf_new 表（需修改period）
DELETE ALL for ATC="Z98A2" or ATC="V03B2"
删除非药品类产品（Z98A2和V03B2是非药品的ATC分类码）
PACK
物理删除上面标记的记录
第二步：给新增表添加辅助字段
ALTER table ndf_new add column dn c(7) / csn / name1 / manu / specifi
添加5个空列：dn(药物编号)、csn、name1(名称)、manu(厂家)、specifi(规格)
第三步：通过CPA表填充厂家和规格信息
use cpa → SET FILTER TO LEFT(cpa.notes,1)<>'Z' AND !EMPTY(PACK_cODE)
打开CPA表，过滤掉：中药(notes以Z开头)和无包装码的记录
INDEX on ALLTRIM(pack_Code) TO s3
对CPA表的pack_Code建索引
SELECT ndf_new → SET RELATION to ALLTRIM(pfc) into cpa addi
ndf_new 通过 PFC 关联 CPA 表（PFC = pack_Code）
REPLACE all dn/csn/name1/manu/specifi with cpa.xxx
从CPA表中提取 dn、csn、名称、厂家、规格 填入 ndf_new
第四步：与参比制剂总表通过DN关联
SELECT 仿制药参比制剂 → INDEX on ALLTRIM(dn) to s5
对参比制剂总表的dn字段建索引
SELECT ndf_new → SET RELATION to ALLTRIM(dn) into 仿制药参比制剂 addi
ndf_new 通过 DN 关联参比制剂总表（用于后续人工比对并补充PFC）
4 PRG 4：汇总所有PFC并同步到GQCE总表
目标：

把参比制剂总表中所有的PFC提取出来，将新增的同步到GQCE标记总表

第一步：提取所有PFC（pfc_1 到 pfc_11 共11列）
select distinc pfc_1 as pfc,序号 as 批次 from 仿制药参比制剂 ... into dbf s1
select distinc pfc_2 ... into dbf s2
... (重复到 pfc_11)
参比制剂总表有11个PFC列（一个药品可能有多个包装规格），分别提取去重
select s1 → append from s2 → ... → append from s11
把11个临时表的数据合并到 s1 中，形成一张完整的PFC清单
copy to 参比制剂_pfc总表
另存为"参比制剂_pfc总表"
第二步：清洗批次字段
REPLACE ALL 批次 WITH STREXTRACT(ALLTRIM(批次),'','-') FOR '-'$批次
如果批次字段含"-"，只保留"-"前面的部分（例如 "44-5" 变成 "44"）
第三步：找出GQCE中没有的PFC，追加进去
select pfc from 参比制剂_pfc总表 ... where pfc not in (sele pfc from gqce) into dbf pfc_新增
SQL查询：找出在参比制剂总表中有、但GQCE总表中还没有的PFC
select gqce → append from pfc_新增
将新增PFC追加到GQCE总表
repl all gqce with "Reference preparation" for empty(gqce)
新加入的记录，gqce字段标记为"Reference preparation"（参比制剂）
replace all 参比批次 with allt(参比制剂_pfc总表.批次) for !eof(...)
同步填写每条记录对应的参比批次号
脚本 2

一致性评价脚本 — 更新过评产品并同步GQCE

PRG 1: 导入两个数据源 → PRG 2: 匹配批准文号筛选过评 → PRG 3: 新过评追加到GQCE → PRG 4: 清理&验证 → PRG 5: 输出最终文件
1 PRG 1：从两个数据源导入新增过评产品
目标：

分别从"药融云"和"上市药品目录集(CIPP)"两个来源，导入本月新增的已过评产品到"一致性评价药物汇总"总表

数据源A：药融云（第三方平台数据）
use 一致性评价药物汇总
打开上一期的一致性评价总表（需事先复制并去掉日期后缀）
INDEX on ALLTRIM(pzwh1) to p1
对总表的"批准文号1"字段建索引
COPY STRUCTURE to GP_STRU → COPY TO GP_YRY
创建一个空结构表 GP_YRY
APPEND FROM ...药融云新增202604.csv type csv
从药融云导出的CSV导入新增过评产品数据（路径需修改）
INDEX on ALLTRIM(pzwh1) to p2 → SET RELATION to ... into 一致性评价药物汇总
通过批准文号关联总表，查看哪些已经存在
DELETE ALL FOR !EOF('一致性评价药物汇总') → PACK
删除已经在总表中存在的记录（去重），只留真正的新增
SELECT 一致性评价药物汇总 → APPEND FROM GP_YRY
将去重后的药融云新增数据追加到总表
数据源B：上市药品目录集 (CIPP)
COPY TO GP_CIPP → APPEND FROM ...一致性评价药物汇总202604.csv
同样的流程，从CIPP导出的CSV导入新增数据
INDEX → SET RELATION → DELETE FOR !EOF → PACK → APPEND
去重→追加，逻辑与药融云完全一致
人工检查
BROWSE LAST FOR LEN(ALLTRIM(pzwh1))<>17
预览批准文号长度不是17位的记录。标准批准文号如"国药准字H20000001"正好17位，不等于17说明有异常，需人工处理（可能是多个文号并列，需拆分到pzwh2、pzwh3等列）
核心逻辑：两个数据源可能有重叠，所以每次导入前都要通过批准文号去重，避免重复记录。
2 PRG 2：匹配批准文号，识别NDF中的过评产品
目标：

在NDF数据库中找出通过一致性评价的产品PFC，这是整个脚本最核心、最复杂的一步

第一步：整理过评批准文号总表
SELECT pzwh1 as 批准文号 FROM 一致性评价药物汇总 INTO dbf 过评批准文号
SELECT pzwh2/pzwh3/.../pzwh6 ... APPEND
把总表中 pzwh1~pzwh6 六列的批准文号全部提取出来，合并成一张"过评批准文号"清单
DELETE ALL FOR EMPTY(批准文号) → INDEX on ALLTRIM(批准文号) to t6
删除空行，建索引
第二步：提取NDF中未在GQCE中的产品
SELECT pfc,name,atc,...FROM ndf WHERE PFC NOT IN (SELECT PFC FROM GQCE) INTO dbf pfc_pzwh
从NDF中提取所有还没在GQCE总表中的产品PFC（候选名单）
ALTER table pfc_pzwh ADD COLUMN pzwh/gqce/dn/specifi
添加辅助列：批准文号、gqce标记、DN编号、规格
第三步：过滤掉不适用的产品类型
DELETE ALL FOR ALLTRIM(DF)='C' OR ALLTRIM(DF)='Z'
删除中药(Z)和联合产品(C)（不适用一致性评价）
DELETE ALL FOR LABCODE='07636'
删除"任意厂家"的产品（labcode 07636 是占位符）
DELETE ALL FOR atc='Z98A2' / 'Z95A0' / 'V03B2' / 'A10E0' / V07A / V05A / T02D / T02C / T03A
删除非药品、中成药等不适用的ATC分类
第四步：关联CPA表获取批准文号
use cpa → SET FILTER → INDEX on pack_Code → SET RELATION PFC into CPA
打开CPA表，通过PFC关联获取每个产品的批准文号
REPLACE ALL PZWH WITH ALLTRIM(CPA.PZWH) ...
把CPA中的批准文号、DN、规格等信息填入候选表
第五步：批准文号数据清洗（重要！）
操作说明示例
STREXTRACT(pzwh,'','(')去掉括号及括号内容"国药准字H123(已过期)" → "国药准字H123"
STREXTRACT(pzwh,'','/')去掉斜杠后内容"H123/原文号" → "H123"
chrtranc 去掉 已注销/注销去掉"已注销""注销"文字"H123已注销" → "H123"
chrtranc 去掉 已过期/过期去掉过期相关文字"H123已过期" → "H123"
chrtranc 去掉 已到期/到期去掉到期相关文字"H123已到期" → "H123"
chrtranc 去掉 已下市/下市去掉下市相关文字"H123已下市" → "H123"
chrtranc 去掉 暂查不到去掉无法查询标记"暂查不到H123" → "H123"
为什么需要清洗？CPA表中的批准文号可能带有各种状态标注（已注销、过期、下市等），这些后缀会导致匹配失败，所以要先清理干净只保留纯文号。
第六步：与过评批准文号匹配 + 排除不适用记录
SET RELATION TO ALLTRIM(PZWH) INTO 过评批准文号
通过清洗后的批准文号，关联"过评批准文号"总表
DELETE ALL FOR '查'/'临研'/'过期'/... $PZWH
删除批准文号中仍包含异常关键字的记录（兜底清理）
DELETE ALL FOR '国药准字S/J/X/Z'$PZWH AND EOF('过评批准文号')
S=生物制品、J=进口、X=体外诊断、Z=中药，如果不在过评名单中就删除
DELETE ALL FOR '国药准字H'$PZWH AND EOF('过评批准文号')
化学药(H)如果不在过评名单中也删除
REPLACE ALL gqce WITH 'PASS' FOR !EOF('过评批准文号') AND !EMPTY(PZWH)
核心操作：在过评名单中找到匹配的产品，标记为 "PASS"
DELETE ALL FOR left(pfc,9)='000037708' and stru<100
特殊处理：厄贝沙坦氢氯噻嗪片（华海）多规格共用文号，仅150MG:12.5MG才是PASS
重点理解：PRG 2 的核心逻辑是——从NDF中取出所有未标记的产品，通过CPA获取其批准文号，清洗文号后与"过评批准文号"名单进行匹配，匹配上的就标记为 PASS。
3 PRG 3：将新过评产品追加到GQCE总表
目标：

把 PRG 2 中标记为 PASS 的产品追加到 GQCE 总表，并补充 DN 和 DF 信息

SELECT pfc,gqce from pfc_pzwh where gqce="PASS" into dbf pass_新增
从候选表中提取所有标记为 PASS 的产品
Select gqce → Append from pass_新增
追加到 GQCE 总表
SET RELATION to pfc into cpa → replace all dn with cpa.dn for EMPTY(dn)
通过CPA补充缺失的DN编号
INDEX on ALLTRIM(pfc) to t7 (ndf) → SET RELATION → REPLACE all df with ndf.df
通过NDF补充剂型(DF)信息
BROWSE last for df="C" or df="Z"
检查是否有中药(Z)或联合产品(C)混入，需记录到Tracker中
4 PRG 4：数据清理与一致性验证
目标：

清除异常记录，填写加入日期，并验证数据一致性

use gqce exclusive → PACK
物理删除之前标记的 df="C" 或 "Z" 的产品
REPLACE all 加入date with "04M2026" for EMPTY(加入date)
新加入的记录填写加入日期（格式为"月份M年份"，需根据当期修改）
SELECT distinct LEFT(pfc,9) as pfc9, gqce FROM gqce INTO dbf tmp6
提取前9位PFC（代表同一药品不同规格）+ GQCE标记
SELECT pfc9, COUNT(*) ... HAVING cnt1<>1
检查同一个PFC9是否有不同的GQCE标记（正常应该只有一个000010264）
验证逻辑：同一个药品（PFC前9位相同）理论上应该有统一的GQCE标记。如果出现同一药品既有PASS又有其他标记，就说明数据有问题。已知 PFC9=000010264 是正常的例外，其他异常需要排查。
5 PRG 5：生成最终提交文件
目标：

输出最终格式的GQCE文件用于提交

SELECT pfc,gqce from gqce into dbf GQCE_MMYY order by pfc
提取PFC和GQCE标记，按PFC排序，输出为 GQCE_MMYY 文件（MMYY替换为实际月份年份）

二、两个脚本的关系与协作

脚本1：参比制剂脚本
输入：NMPA发布的新增+勘误CSV
处理：更新参比制剂总表 → 匹配PFC
输出：更新后的GQCE总表（标记 "Reference preparation"）
→
脚本2：一致性评价脚本
输入：药融云 + CIPP 新增过评CSV
处理：匹配批准文号 → 标记PASS
输出：最终GQCE_MMYY文件（标记 "PASS"）

两个脚本共同维护 GQCE 总表：

  • 脚本1 负责标记"Reference preparation"（被选为参比制剂的产品）
  • 脚本2 负责标记"PASS"（通过一致性评价的产品）
  • 通常先执行脚本1，再执行脚本2，因为脚本2需要使用脚本1更新后的GQCE
